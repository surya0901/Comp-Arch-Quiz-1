Cache memory

Locality and the hierarchy

Temporal locality: recently used items are used again soon (loop instructions, loop counters). Spatial locality: items near recently used ones are used soon (sequential code, arrays). The hierarchy (registers, SRAM cache, DRAM, disk) gives the illusion of memory as big as disk and almost as fast as SRAM.

A block (line) is the unit copied between levels. Hit rate = hits / accesses. Miss rate = 1 − hit rate. Miss penalty is the time to bring the block from the lower level. Hit time ≪ miss penalty.

Her four questions

QuestionAnswer
Q1 Block placementDirect mapped: one place. n-way: any of n places in one set. Fully associative: anywhere.
Q2 Block identificationIndex picks the set, compare the tag of every way in that set, check the valid bit.
Q3 Block replacementDirect mapped has no choice. Otherwise prefer an invalid entry, then LRU (simple for 2-way, manageable for 4-way, too hard beyond) or random (about as good as LRU at high associativity).
Q4 Write strategyWrite through or write back on a hit, write allocate or no write allocate on a miss.

Her slide example: memory block 12 in an 8-block cache goes to block 4 if direct mapped (12 mod 8), to set 0 if 2-way with 4 sets (12 mod 4), and anywhere if fully associative.

Splitting the address

TagIndexOffset
address bits = log2(memory size in bytes) (or given, e.g. addr[53:0] = 54) offset bits = log2(block size in bytes) #blocks = cache data size / block size #sets = #blocks / ways index bits = log2(#sets) (0 for fully associative) tag bits = address bits − index − offset

Every doubling of ways halves the sets, so index loses 1 bit and tag gains 1 bit. Tag + index stays constant.

Her slide example (address 1200): 64 blocks, 16 bytes per block, 32-bit address. Block address = 1200 / 16 = 75. Cache block = 75 mod 64 = 11. Fields are tag 22, index 6, offset 4.

Tag 22 bits [31:10]Index 6Off 4

Total cache size in bits

bits per block = 1 (valid) + tag + 8 × block bytes (+1 dirty if write back) total bits = #blocks × bits per block

Her Examples sheet P3 counts valid + tag + data only, so use that unless the question mentions write back or a dirty bit. Her slide example: 64 KB of data, 1-word blocks, 32-bit address gives 214 blocks × (1 + 16 + 32) = 802,816 bits ≈ 100 KB.

How to trace an address list (the HW2 P2 method)

  1. Addresses are byte addresses unless told otherwise. If a block has 32 words of 4 bytes, the block is 128 bytes.
  2. Block address = floor(byte address / block bytes).
  3. Index (set) = block address mod #sets. Tag = block address / #sets.
  4. Hit if that set already holds the block. Otherwise miss: fill an empty way, or evict the LRU way.
  5. For 2-way and 4-way, keep each set's LRU order written next to it as you go.
  6. At the end, list each cache block (or set and way) with the memory block in it, for example "block 4 holds Mem[512 to 639]".

Her word address example (slides 14 to 18): 8 one-word blocks, sequence 22, 26, 22, 26, 16, 3, 16, 18. Word 22 = 10 110, so index 110, tag 10. 18 = 10 010 evicts 26 from index 010.

Her associativity example (slides 35 and 36), 4 blocks, block sequence 0, 8, 0, 6, 8: direct mapped 5 misses, 2-way 4 misses, fully associative 3 misses.

Writes

Write through

Write cache and memory on every write. Simple, memory always current, helps coherence. More traffic and slow writes: base CPI 1, 10% stores, 100-cycle memory gives CPI 1 + 0.1 × 100 = 11. Fix with a write buffer so the CPU stalls only when it is full. Usually paired with no write allocate.

Write back

Write only the cache. Memory is updated when a dirty block is evicted. Less traffic, but a dirty eviction costs a longer miss penalty. Usually paired with write allocate. A write buffer lets the new block be read first.

Performance formulas, in her style

Memory stall cycles = accesses × miss rate × miss penalty AMAT = hit time + miss rate × miss penalty AMAT (3 levels) = L1hit + L1miss × (L2hit + L2miss × (L3hit + L3miss × DRAM)) Clock cycle = 1 / f. Memory cycles = memory time / clock cycle CPI (L1 only) = base + L1 miss rate × memory cycles CPI (with L2) = base + L1 miss rate × L2 time + global miss rate × memory cycles Write back AMAT = hit + miss rate × (dirty% × dirty penalty + clean% × clean penalty)

Her write buffer convention (Examples P5b): "eliminates 50% of the stall cycles" is computed by multiplying the whole dirty penalty by 0.5: AMAT = 1 + 0.15 × (20 × 0.2 × 0.5 + 8 × 0.8) = 2.26, speedup 2.56 / 2.26 = 1.13. Follow her convention on the quiz.

Virtual memory

DRAM acts as a cache for disk. Each process gets a private virtual address space, protected from others. The CPU (MMU) and the OS translate virtual addresses to physical ones.

Cache termVM term
BlockPage (virtual), frame (physical)
MissPage fault, millions of cycles, handled by OS software through an exception
TagVirtual page number (VPN)

Translation

Virtual page number (VPN)Page offset
Physical page number (PPN)Page offset (same)
offset bits = log2(page size) VPN bits = VA bits − offset bits → #PTEs = 2^VPN bits PPN bits = PA bits − offset bits (PA bits = log2(DRAM size)) Page table size = #entries × entry size

The page table register (PTBR, plus PTLR for length) points to the current process's table in DRAM. Each process has its own table, which is why two programs can use the same virtual addresses.

PTE contents: PPN plus valid, dirty, reference (use) and protection bits. Valid = 0 means the page is unallocated or swapped to disk.

Design choices forced by the huge miss penalty

  • Fully associative placement (any page in any frame) and smart replacement, to minimize page faults.
  • LRU approximated with the reference bit: set on access, cleared periodically by the OS. A page with bit 0 has not been used recently.
  • Write back only. Write through to disk would take millions of cycles per write. The dirty bit marks pages that must be saved before eviction.
  • Page faults handled in software, since the penalty dwarfs the handler cost and the OS can choose victims cleverly.

TLB

Without a TLB, every access needs two memory accesses: one for the PTE, one for the data. The TLB is a small, fast cache of PTEs inside the CPU. Slide numbers: 16 to 512 entries, 0.5 to 1 cycle hit, 10 to 100 cycles miss, 0.01% to 1% miss rate. TLBs may store ASIDs so they need not be flushed on every context switch. Some entries can be wired down.

TLB hit → physical address immediately TLB miss, PTE valid → load PTE into TLB, retry (hardware or software handler) TLB miss, PTE invalid → PAGE FAULT: OS finds page on disk, picks a victim (writes it back if dirty), loads page, updates PT, restarts the faulting instruction

How to do the TLB and page table trace (HW2 P6 and HW3 P2 style)

  1. VPN = address / page size. For 4 KiB pages that is the hex address without its last 3 hex digits: 0x123d → VPN 0x1.
  2. Search all valid TLB tags (fully associative). Found: TLB hit, reset its "time since last access" to 0.
  3. Not found: look up page table entry VPN. Valid: PT hit, copy into the TLB.
  4. Invalid: page fault. Give it the next physical page number above the largest one in use, mark PT valid, copy into the TLB.
  5. When copying into the TLB, use an invalid entry first, else evict the entry with the largest time since last access (LRU). Add 1 to every other entry's time.
  6. For a 2-way TLB, set = VPN mod 2 and tag = VPN / 2. For direct mapped, index = VPN mod #entries.

Page table structure: the size problem

32-bit VA with 4 KB pages has 220 PTEs × 4 B = 4 MB per process. Her slide example: 40-bit VA, 16 KB pages, 36-bit PA, 4 status bits gives 240 / 214 = 226 entries, each 4 + 36 = 40 bits wide, so 226 × 5 bytes = 335 MB per process. She counts the full 36-bit physical address in the entry width, so do the same unless told otherwise. Three fixes:

1. Hierarchical (forward mapped) paging

Page the page table. Her example: 32-bit VA, 1 KB pages. Offset 10, VPN 22 split into p1 = 12 (outer table index) and p2 = 10 (offset within the page of the inner table).

p1 = 12p2 = 10d = 10

Only the inner tables actually in use need to be in DRAM. Cost: one memory access per level on a TLB miss. For 64-bit VA with 4 KB pages there are 252 pages. With 210-entry inner tables the outer table still has 242 entries, a 2nd outer table still has 232, so you need more levels and possibly 4 memory accesses per translation.

entries per page-sized table = page size / PTE size bits per level = log2(that) levels = ceil(VPN bits / bits per level) memory refs on a TLB miss = levels (then +1 for the data itself)

2. Hashed page table

Common when address spaces exceed 32 bits. Hash the VPN (mod the hash table size). Each bucket holds a chain of elements: (VPN, frame, next pointer). Walk the chain comparing VPNs. Clustered variant: each entry covers several pages (e.g., 16), good for sparse address spaces.

3. Inverted page table

One entry per physical frame, one table for the whole system, sized by DRAM rather than by the virtual address space. Each entry holds (pid, p). The logical address (pid, p, d) is searched for. The index i of the matching entry is the frame number, and the physical address is (i, d). Use a hash to limit the search, and a TLB to avoid it most of the time. Shared memory is hard because each frame holds one mapping. Details in the Conceptual answers tab.

Logical vs virtual vs physical

Logical addresses come from Intel's segmented model (segment selector + offset). Adding the segment base gives the virtual (linear) address, which the MMU then pages into a physical address. Segmentation was largely abolished in 64-bit mode. Users can see logical addresses but never physical ones.

Conceptual answers

She asks you to "explain trade-offs". A strong answer names the mechanism, says what goes up, what goes down, and why. Try each one yourself before opening it.

1. If we double and keep increasing associativity in a cache of given size, how is performance affected? Which metrics increase or decrease, and why?

Structure. The number of blocks is fixed, so sets = blocks / ways halves with each doubling. Index loses 1 bit and tag gains 1 bit. Offset is unchanged. At fully associative there is 1 set, no index, and the tag is the whole block address.

Goes down:

  • Conflict misses, because blocks that map to the same set can now coexist. So miss rate drops.
  • But with diminishing returns. Her slide (64 KB D-cache, 16-word blocks, SPEC2000): 1-way 10.3%, 2-way 8.6%, 4-way 8.3%, 8-way 8.1%. Most of the gain is in the first doubling.
  • Compulsory and capacity misses do not change, since the size and block size did not change.

Goes up:

  • Hit time: n tag comparators in parallel, then an n-to-1 mux to select the way. Unlike direct mapped, data cannot be sent before the tag check finishes.
  • Power: n tags and n data ways are read on every access (why way prediction exists).
  • Tag storage (1 more bit per block per doubling) and area (comparators).
  • Replacement complexity: LRU is simple for 2-way, manageable for 4-way, too hard beyond, so random is used.

Net effect. AMAT = hit time + miss rate × miss penalty. The miss rate term shrinks less and less while hit time keeps growing, so past some point AMAT gets worse. If the cache sets the clock cycle, a slower hit slows everything. That is why L1 stays small and lowly associative, while L2 and L3 (where the miss penalty is large) use higher associativity.

2. How does the inverted page table work?

Problem. A normal page table has one entry per virtual page per process. For large address spaces that is huge and mostly empty (her example: 335 MB per process).

Idea. Track physical pages instead. One entry per frame of DRAM, one table for the whole system. Its size depends on DRAM, not on the virtual address space or the number of processes.

Entry: the process id and virtual page number currently held in that frame (pid, p), plus control bits.

Lookup:

  1. CPU issues logical address (pid, p, d).
  2. Search the table for an entry matching (pid, p). In practice hash (pid, p) to limit the search to one or a few entries, following a chain on collisions.
  3. If entry i matches, then i is the frame number. Physical address = (i, d).
  4. No match means a page fault.

Trade-offs. Much less memory for page tables. But a lookup is a search, not a direct index, so it takes longer: common case about 1 memory reference with a good hash, worst case a long chain walk. So a TLB is essential. Shared memory is hard, since a frame holds only one (pid, p) mapping. It records only resident pages, so the OS still needs other structures for pages on disk.

3. What happens if we increase the block size in a fixed-size cache?

Miss rate first drops: more spatial locality is captured, so fewer compulsory misses. Then it rises: fewer blocks fit, so more conflict and capacity misses, and part of each large block is never used (pollution). Miss penalty always grows, since more bytes must be transferred. Tag bits per byte of data drop (less overhead). Best block size balances the two, which is why her slide says the larger penalty "can override the benefit of reduced miss rate". Critical word first and early restart reduce the penalty.

4. Write through vs write back

Write through keeps memory always up to date, so evictions are free and coherence is simple. But every store goes to memory: more traffic, slower writes, and a write buffer is needed (the CPU stalls only when it is full). Write back writes only the cache. Repeated writes to a block cost one memory write at eviction, so traffic is far lower. But it needs a dirty bit, evicting a dirty block costs a longer miss penalty (her AMAT problems), and memory can be stale. Virtual memory always uses write back because a disk write costs millions of cycles.

5. TLB miss vs page fault. Why is one handled in hardware and the other in software?

A TLB miss means the PTE is not cached, but the page may still be in DRAM. It costs 10 to 100 cycles, so it can be handled by a hardware walker or a fast exception handler that copies the PTE and retries. A page fault means the page is not in DRAM at all. It costs millions of cycles for the disk access, so the OS handler's cost is negligible, and software can make smart replacement choices (reference bits, write back of dirty pages). The handler must catch the miss before the destination register is overwritten, then restart the faulting instruction.

7. Larger page size: advantages and disadvantages

Pros: fewer PTEs, so a smaller page table. Each TLB entry covers more memory (larger TLB reach), so fewer TLB misses. Disk transfers are more efficient per byte. Cons: more internal fragmentation (wasted space in the last page of each region), longer page fault service time, and more memory wasted if only a small part of a page is used.

8. Why add an L2 (or L3)? When does it not pay?

L2 cuts the L1 miss penalty: a miss that hits in L2 costs tens of cycles instead of hundreds. L1 can then stay small and fast to match the clock, while L2 is large and highly associative. Her example: CPI 9 drops to 3.4 (2.6× faster). The gain is largest when memory is slow, since L2 hides it. A level does not pay when its hit time is high and its local miss rate is high, because then most misses pay the extra lookup and still go to memory. It also costs area, power and complexity.

9. In HW2 P2, why were all the misses compulsory?

Every address was below 2048 bytes, far less than the 8 KB cache, so every block had tag 0 and no two blocks ever competed for the same cache location. Each block was missed exactly once, on first touch. That is why the direct mapped cache (128-byte blocks) had more hits than the 4-way cache (64-byte blocks): bigger blocks prefetch more neighbors, which is spatial locality, and associativity had no conflicts to remove.

(d) [conceptual] Both caches in (b) hold the same amount of data. Explain why the 2-way cache did so much better, and what it paid for that.

Solution 1(d)

The program alternates between blocks 3 and 11, 4 and 12, 5 and 13. In the direct mapped cache each pair maps to the same block (11 mod 8 = 3), so they keep evicting each other: every miss after the first touch is a conflict miss. In the 2-way cache each pair shares a set but fits in its two ways, so all conflict misses disappear and only the 7 compulsory misses remain. The cost: one more tag bit per block (2,112 vs 2,104 bits), two comparators and a way mux, which raise hit time and power, plus LRU state per set.

Problem 2. Virtual memory

(a) [quantitative] A system has 36-bit virtual addresses, 4 GiB of DRAM, 8 KiB pages and 4-byte PTEs. How many PTEs does a single-level page table need, and how much memory does it take? Is 4 bytes enough for a PTE?

Solution 2(a)
offset = log2(8K) = 13 VPN = 36 − 13 = 23 bits #PTEs = 2^23 = 8,388,608 size = 2^23 × 4 B = 2^25 B = 32 MiB per process PA = log2(4 GiB) = 32 bits → PPN = 32 − 13 = 19 bits

19 PPN bits plus valid, dirty, reference and a few protection bits is well under 32, so 4 bytes is enough.

(b) [quantitative] Each level of the page table must fit in one page. How many levels are needed, and how many memory references does a TLB miss cost?

Solution 2(b)
entries per page = 8 KiB / 4 B = 2^11 → 11 VPN bits per level levels = ceil(23 / 11) = 3 (e.g. 1 + 11 + 11 bits)

A TLB miss walks 3 levels, so 3 memory references for translation, plus 1 for the data itself.

(c) [conceptual + quantitative] How many entries would an inverted page table need on this system? Explain how it translates an address and why it needs a TLB.

Solution 2(c)

One entry per frame: 232 / 213 = 219 = 524,288 entries, for the whole system, regardless of the 36-bit virtual space or the number of processes. Each entry holds (pid, VPN). Translation hashes (pid, VPN), follows the chain until an entry matches, and the index i of that entry is the frame number, so PA = (i, offset). No match is a page fault. Because translation is a search (about 1 reference in the common case, a chain walk in the worst case) instead of a direct index, it is slower, so a TLB is needed to make most translations skip it.

0x51000x5TLB miss, PT hit0x5 was evicted earlier. Evicts LRU tag 0x70xa100

Final TLB (V, tag, PPN, time): (1, 0x2, 7, 3), (1, 0x5, 10, 0), (1, 0x8, 5, 2), (1, 0xa, 13, 1). Page table changes: PT[7] = valid, 12. PT[10] = valid, 13.

Note the last access: 0x5 was a TLB hit at the start, but LRU evicted it, so now it misses in the TLB yet still hits in the page table. Watch for this on the quiz.

(e) [conceptual] Why does virtual memory use write back and handle page faults in software, while caches can use write through and handle misses in hardware?

Solution 2(e)

A page fault costs millions of cycles (disk access). Write through to disk on every store would be impossibly slow, so pages are written back only when a dirty page is evicted, a whole page at a time. Because the penalty is so large, the time spent in an OS handler is negligible, and software can use smarter replacement (reference bits approximating LRU, preferring clean pages) to reduce the fault rate. A cache miss costs only tens to hundreds of cycles, so it must be handled by fast hardware, and write through is workable with a write buffer.

D2. Which cache block?

Cache with 64 blocks of 16 bytes. Which cache block does byte address 2600 map to if direct mapped? Which set if 4-way?

Answer

Block address = 2600 / 16 = 162 (floor). Direct mapped: 162 mod 64 = 34. 4-way has 16 sets: 162 mod 16 = set 2.

D3. CPI with an L2

Base CPI 2, 2.5 GHz, memory 80 ns, L1 miss rate 10%. (a) L1 only. (b) Direct mapped L2, 15 cycles, global miss rate 4%. (c) 8-way L2, 22 cycles, global miss rate 2.5%.

Answer
cycle = 0.4 ns → memory = 200 cycles (a) 2 + 0.10 × 200 = 22 (b) 2 + 0.10 × 15 + 0.04 × 200 = 2 + 1.5 + 8 = 11.5 (c) 2 + 0.10 × 22 + 0.025 × 200 = 2 + 2.2 + 5 = 9.2

The 8-way L2 is slower per hit but its lower global miss rate wins because memory is so expensive.

D4. AMAT with dirty blocks

Write back cache, 30% of evicted blocks dirty, miss rate 10%, hit time 1 cycle, miss penalty 10 cycles clean and 25 cycles dirty. (a) AMAT. (b) Speedup if a write buffer eliminates 40% of the write back stall cycles.

Answer
(a) 1 + 0.10 × (0.3 × 25 + 0.7 × 10) = 1 + 0.10 × 14.5 = 2.45 (b) 1 + 0.10 × (0.3 × 25 × 0.6 + 0.7 × 10) = 1 + 0.10 × 11.5 = 2.15 speedup = 2.45 / 2.15 = 1.14

Uses her convention from Examples P5b (scale the dirty penalty).

D5. Page table size

44-bit virtual address, 8 KB pages, 38-bit physical address, 4 status bits, all pages in use, no disk addresses stored. Total page table size per process?

Answer
#entries = 2^44 / 2^13 = 2^31 width = 4 + 38 = 42 bits (her slide method: status bits + full PA width) size = 2^31 × 42 bits = 2^28 × 42 bytes ≈ 11.3 GB (10.5 GiB)

If you use only the PPN (38 − 13 = 25 bits), the width is 29 bits and the size 228 × 29 B ≈ 7.25 GiB. Either way it is impossibly large, which is the point of multi-level and inverted tables. On the quiz, follow her slide's method and state your assumption.

D6. Two-level split

32-bit VA, 4 KB pages, 4-byte PTEs, each inner table fits in one page. Give the p1, p2, d split.

Answer

d = 12. Inner table holds 4096 / 4 = 1024 entries, so p2 = 10. p1 = 32 − 12 − 10 = 10.

p1 = 10p2 = 10d = 12

D7. Her word address trace

Direct mapped, 16 one-word blocks, word addresses 1, 4, 8, 5, 20, 17, 19, 56, 9, 11, 4, 43, 5, 6, 9, 17. Hits and final contents? (Part 1 slide 22.)

Answer

Index = address mod 16. Hits: 5, 9, 17 (3 hits, 13 misses). 20 evicts 4 at index 4, then 4 evicts 20 again. 43 evicts 11 at index 11. Final: index 1 = 17, 3 = 19, 4 = 4, 5 = 5, 6 = 6, 8 = 56, 9 = 9, 11 = 43. Others empty.
